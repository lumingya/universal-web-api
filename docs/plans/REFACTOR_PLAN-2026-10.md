> 执行方式：**每步一个 commit，每步必须 `pytest` 全绿才能进入下一步。**

## 铁律

1. **不重写。** 只做局部、可验证的结构调整。
2. **每步一个 commit**，commit 前 `pytest -q -m "not browser and not real_browser"` 必须为 **0 failed**。
3. **任何结构性改动都有棘轮锁住**，只允许变好，不允许变差。
4. 不可自动验证的改动（拆函数、改依赖方向）必须**先有测试再动**，或**同步补测试**。
5. 单步失败 → `git revert` 该步，不强行推进。

## 验收脚本

```bash
# 每步提交前执行
uv run --no-sync pytest -q -m "not browser and not real_browser"
uv run --no-sync ruff check .
```

### 本轮额外发现并修复的真实缺陷

**`patch_drissionpage.py` 的失败是完全静默的（步骤 9）**
`main()` 从不返回非零退出码，因此 `bootstrap.py` 里
`if result.returncode != 0` 的告警**永远不会触发**。而本项目启动时直接改写
DrissionPage 源码，一旦注入点因升级而消失，表现只是"网络监听模式不可用"，
进程照常启动，极难排查。已改为明确退出码（0/1/2）+ 写回后复核
（`verify_patch()`），并新增 10 项测试。

### 步骤 7 的注册表模式（可复用于其它派发链）

`_execute_action` 的改造分两步，顺序不能反：

1. **先把内联分支提出成方法**（7a），让每个分支变成单行委托；
2. **再把整条链换成查表**（7b）。

直接在满是内联实现的长链上改查表，等于同时做两件事，无法验证等价性。
分两步后，第 1 步可以用"方法体与分支体逐字节相同"来证明零行为变化
（11/11 校验通过），第 2 步则因为所有分支都互斥等值比较而天然等价。

查表带来两个**原结构没有的失效模式**，必须配测试：
- 表里登记了不存在的方法名 → 运行时 AttributeError；
- 表与 `command_defs.ACTION_TYPES` 不同步 → UI 上能选的动作在运行时
  落到"未知类型"。当前两侧都是 23 项且完全对齐，测试断言集合相等。

另有一处类型陷阱：字典查找要求键可哈希，而 `action_type` 来自用户配置，
可能是 dict/list。原 `if/elif` 链用 `==` 比较只会失配后落到 else，无条件
查表则会抛 TypeError——把一个配置错误升级成崩溃。实现加了 `isinstance`
判断，并配了参数化测试。

### 同一配方在 execute_step 上踩到的坑（值得记住）

步骤 10 把这套配方用在 `execute_step` 上时，第一版直接照抄 `_execute_action`
的 `yield from handler(...)` 写法，**当场跑挂了两个集成测试**：
`TypeError: 'NoneType' object is not iterable`。

原因：两处注册表看着像，语义并不同。`_execute_action` 的所有处理器都返回
值；而 `execute_step` 的 11 个处理器里**只有流式步骤是生成器**，其余 10 个
只是执行副作用后返回 None。对 None 做 `yield from` 必然抛错。

结论：**复用配方不等于复用实现**。每次套用都要重新确认处理器的返回契约，
并且——这一条更有价值——正是已有的集成测试在几秒内把它抓住了。这也是铁律
第 2 条（每步必须全绿才能提交）实际发挥作用的一次。

### 步骤 6 的拆分方法（可复用于其它巨型函数）

CC 357 的函数不是靠"勇气"拆的，而是靠**每一步都能拿出等价性证据**。
四次提交分别用了三档证据，代价递增：

| 档 | 适用 | 做法 | 证据 |
| --- | --- | --- | --- |
| **A · 字节搬家** | 被提取的块与外层只有数据耦合，没有 `break`/`continue`/`return` | **形参名与原有局部变量完全同名**，方法体只需改缩进 | `ast.get_source_segment` 逐字节比对（6b：159 行一致） |
| **B · 语句等价** | 块内有控制流跳转，必须改写成返回值 | 引入出口对象（如 `_InterruptOutcome`），跳转 → `return` | AST 展平后逐条比对，剔除已知改写（6c：21/21 语句一致） |
| **C · 行为差分** | 无法结构化比对（如守卫重排） | 改前/改后双实现同输入对比 | 归一化 `id`/`created` 后逐字节比对（6a：56 组零差异） |

三档都要求**先有测试或同步补测试**。步骤 6 累计新增 56 项测试，其中
入口守卫、中断出口、Battle 判定等都是**提取之后才第一次变得可测**的路径——
这正印证了评估里的判断：不是不写测试，是结构不允许写。

拆到 289 之后，剩下的块都不再是"独立的阶段"，而是与主循环变量深度
交织（逐步预处理段会写 13 个后续要用的变量，动作派发 Try 的三个
handler 都以 break 收尾）。继续拆需要先把循环状态收敛成显式的状态对象，
风险等级上升，因此**暂停在 289，转入步骤 7**。

### 一条重要的结构性结论（供步骤 6/7 参考）

类型检查全量跟进导入时出现 **1415 条 attr-defined**，绝大多数源于项目的
**mixin 组合模式**：如 `WorkflowExecutorSendMixin` 直接使用
`self._attachment_monitor` / `self.tab`，而这些属性由最终组合类里的其它 mixin
提供，单独分析某个 mixin 时静态检查看不到。即 mixin 之间靠**隐式契约**耦合。
拆分巨型类时应顺带把这些契约显式化（宿主类声明或 Protocol），
否则类型检查的收益会被这类噪音长期掩盖。

### 差分测试的两个易踩坑（步骤 20 实测，供后续步骤复用）

给 `app/core/browser/media.py`、`app/core/stream_monitor.py` 这类"吞异常"很重的
浏览器代码做双实现差分时，有两条坑会让你得到**假的"零差异"**：

1. **`ElementFinder` / `media_extractor` 是函数体内局部导入**（`_extract_media_after_stream`
   开头两行）。所以 `monkeypatch` 必须打在**源模块** `app.core.elements` 上，
   打到 `media.py` 的模块属性上无效——异常会被函数里的 `except Exception` 吞掉，
   表现为"结果恒为空、提取器一次都没调用"。
2. **假件的方法签名必须与实际调用形式一致**：`finder.find_all(sel, timeout=...)` 是
   **关键字**参数；`extractor.extract_media(target, config=..., container_selector_fallback=...)`
   两个都是关键字。签名的参数名写错同样表现为被吞掉的 `TypeError`。

判别方法：差分脚本里加**变异测试**——故意把重构后的逻辑改坏，看差分能不能报差异。
报不出来就说明该路径根本没被覆盖，此时的"零差异"没有意义。步骤 20b 就是靠这个
发现前两轮差分是空转的（0 个场景进入轮询），补桩后 4000 场景里有 1861 个真正
进入轮询，6 个变异捕到 5 个，剩下 1 个（盲等的页面级补扫子分支）明确记为已知盲区。

### 变异测试的安全边界（步骤 23b 实测）

变异测试（故意改坏实现、看差分能否报差异）是验证差分有没有牙齿的唯一可靠
手段，但它有个前提：**被改坏的实现必须打不到持久化路径**。

步骤 23b 里，一个把空值改写成 `"x"` 的变异走了正常的配置保存流程，把
`"post_upload_input_selector": "x"` 写回了随仓库分发的 `config/sites/*.json`，
12 个站点配置文件被污染，3 个站点配置测试因此失败。排查时一度误判为
"重构引入的回归"，实际是变异残留。

**规则**：变异只能打在不写盘的纯函数上；若必须覆盖有副作用的函数，
先把数据目录快照，跑完强制还原，并在收尾时 `git status` 确认没有数据文件
被动过。差分脚本本身也要避免触发任何保存逻辑。

### 差分与单元测试必须两个都跑（步骤 24b / 25b 反复验证）

这一轮几次出现"变异没被差分捕获"。逐条查下来，没有一次是等价变异，全是
**差分生成器没造出能触发它的输入**：

| 变异 | 漏网原因 | 谁抓住了它 |
| --- | --- | --- |
| 顶层 `file_paste` 必须是 dict | 生成器从不产生顶层非 dict | 单元测试 |
| audio 显式 filename 被默认名覆盖 | 从不给 input_audio 配 filename | 补测试 + 扩生成器 |
| audio `data=""` 时仍生成 data URI | 从不产生空字符串 data | 补测试 + 扩生成器 |
| `format` 加 `strip()` | 生成器只放了 `" midi "`（strip 后仍非法） | 单元测试 |
| 非 dict 守卫 | 生成器只产生 dict | 单元测试 |

结论：**差分能证明"改得对不对"的覆盖面，完全取决于生成器造得出多少种输入**。
所以流程固定为三步——先看结果分布（成功/各错误码都要有量）确认生成器不是空转，
再跑差分看差异数，最后跑变异看有没有漏网的；漏网的先判断是"等价变异"还是
"生成器盲区"，是后者就补测试并扩生成器，重跑到捕获为止。

### 变异漏网的三种归宿，必须逐个判定并留下结论

不能只看"变异测试有几个没捕到"，漏网的每一个都要有归属。这一轮 22 个变异里
3 个漏网，判定结果：

| 变异 | 归属 | 处置 |
| --- | --- | --- |
| B6 `mode` 加 strip | 测试盲区：`default["mode"]` 就是 `"all"` | 改用非默认成员 `" first "` 重写用例 |
| B21 `src_allow_patterns` 空结果不写入 | 测试盲区：`default["src_allow_patterns"]` 就是 `[]` | 预置哨兵值 `["sentinel"]` 再断言 |
| B1 `selector` 回退改 `default[...]` | **等价变异**：`default["selector"] == "img"` | 证明后接受 |
| B5 枚举去掉 `or ""` | **等价变异**：无假值的 `str()` 会落进枚举集合 | 证明后接受 |
| B22 归一化表顺序反转 | **等价变异**：19 个键两两不同、无顺序依赖 | 证明后接受 |

**"断言它等价"不算证明**。三条都是跑脚本实测出来的：读默认值、枚举假值的
`str()` 结果、归一化表的键是否去重后仍为 19。

反过来，测试盲区的信号很固定：**期望值恰好等于默认值**。写用例时如果断言的是
"保持默认"，要先确认默认值不等于归一化后的值，否则这条用例对任何改动都无感。

### 外部输入必须用 monkeypatch 顶掉，否则差分永远测不到那段逻辑

步骤 27b 的 `_normalize_models` 会读一份别名覆盖配置文件
（ARENA_MODEL_ALIAS_OVERRIDES_PATH）。**该文件在当前环境里是空的**，也就是说
不干预的话，`override` 永远是 `{}`，覆盖查找、`search_name` 覆盖值、覆盖里的
额外别名这三条分支一个都走不到——差分跑十万次也是空转。

做法是在差分脚本里对两个模块各自 patch `_load_alias_overrides`，并让生成器
随机产出覆盖配置（` search_name ` 与 `aliases` 各若干种形态，含非 list 的非法值）。

**凡是读配置、读文件、读环境变量的函数，先确认被测环境里那份数据长什么样；
是空的最好先 patch 成随机数据再跑差分。**
