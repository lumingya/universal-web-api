## 一、结论先行

**不建议以当前默认配置将控制面板/API 暴露到公网或不可信局域网。** 最紧迫的是：默认关闭的管理认证与开放 CORS（S1），叠加一个会原样导出 `.env` 的只读备份接口（S13）；其次是将上游媒体保存为可在应用同源访问的活动格式（S8、S9）。此外，配置模板具有误导性，命令文件热加载可在配置暂时损坏时清空全部命令，后台调试捕获可能持久化聊天响应。

共记录 **38 条**：P1 高优先级 **6**、P2 中优先级 **15**、P3 低优先级 **17**；其中安全/隐私类 `S` 14 条、功能问题 `B` 8 条、优化/仓库卫生 `H` 14 条、测试可复现性 `T` 2 条。**数量不等于 38 个独立可利用漏洞**：例如 S13 是 S1 在备份接口上的高价值具体表现，S3 与 S2 的信任边界相连；标记“条件性/静态”的条目尚无真实浏览器或网络攻击验证。

### 现在就做的部署缓解

1. **隔离服务**：在完成修复前仅绑定可信回环/内网，经防火墙或可信反向代理收紧访问；显式启用服务和仪表板认证，使用不同的强令牌；CORS 限制为必要的准确来源。对 `/api/settings/backup` 单独强制认证，不能仅依赖默认关闭的全局开关。
2. **保护凭据**：若曾把服务暴露给不可信主体，检查访问日志、已导出的备份和 `logs/network_parser_debug`，按实际暴露范围轮换 `.env` 中的令牌/密钥。不要把完整备份文件直接分享、提交或发送给第三方。
3. **关闭高风险输出**：将 `NETWORK_DEBUG_CAPTURE_ENABLED` 显式设为 `false` 并确认运行时值；暂时限制 `/media`、`/download_images` 外部访问，不允许以同源内联方式打开未验证的 SVG/HTML。
4. **限制自定义代码**：只有可信管理员才能安装解析器、配置 Python/JS 命令。AST 过滤不能替代 OS 级隔离。

## 二、证据口径与验证范围

- **[实测]**：合成数据、无网络 mock、`httpx.ASGITransport` 进程内 HTTP、Node VM 或短小临时文件/桩；**不是**真实浏览器或公网攻击验证。
- **[静态/条件]**：代码路径足以说明前置条件和风险，但没有在真实部署、CDP、DNS 重绑定、恶意第三方页面或用户点击场景完成利用验证。
- **[优化]**：容量、可维护性和坏输入健壮性建议；不表示已发生生产故障。

轻量基线：226 个 Python 文件语法检查通过；33 个项目 JS 文件 `node --check` 通过；Ruff 的选定语法/未定义名规则有 5 个 F821。剔除依赖本机私有配置/浏览器的用例后，独立子集 **544 passed、30 deselected**。更宽的首轮为 **548 passed、74 failed、9 deselected**：64 个失败归因缺失/过期的本地 fixture，9 个为站点自动发现断言（B1），1 个为缺失的开发依赖 `httpx`（T2）；不能声称“全套测试通过”。**没有**安装 Playwright/Chromium、运行重度浏览器 E2E、截屏、加载大文件或做高并发压力测试。
